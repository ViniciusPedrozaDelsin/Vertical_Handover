1. MODEL ANALYZED
--------------------------------------------------------------------------------
Keras file used for all measurements: RMSE_RL_1_old.keras
(confirmed by the author to be the model that produced the paper results)

Inputs per candidate network:
  - protocol: 1 integer (index 0..6)
      WiFi-2.4GHz=0, WiFi-5GHz=1, NB-IoT=2, LoRa-868=3, LTE-4G=4, 5G-N78=5, 5G-N28=6
  - velocities: 3 floats (relative velocity to the AP over the last 3 steps)
      computed from the last 4 distances: (d[i+1]-d[i]) * 10 / 30, clipped to [-1, 1]
      (x10 converts per-100-ms to per-second; 30 m/s = VEL_SCALE)
  - inputs: 8 floats, order: RSSI, SNR, Throughput, BER, FEC, PC, MC, HC
      min-max normalized across candidates (0 = best value):
        benefit (RSSI, SNR, Throughput, FEC): (max - x)/(max - min)
        cost    (BER, PC, MC, HC):            (x - min)/(max - min)
        constant column (max == min): 0

Architecture:
  - Embedding: 7 protocols -> 4-dim vector (Glorot uniform init)
  - LSTM: 8 units, tanh, sequence of 3 time steps, 1 feature
  - Dense 8 -> 1, tanh ("lstm_scalar")
  - Concatenate: 4 (embedding) + 1 (LSTM) + 8 (parameters) = 13 inputs
  - Dense 32 -> BatchNorm -> ReLU
  - Dense 64 -> BatchNorm -> ReLU -> Dropout 0.25
  - Dense 32 -> BatchNorm -> ReLU -> Dropout 0.25
  - Dense 16 -> BatchNorm -> ReLU
  - Output Dense 1, linear
Total parameters: 6,118 (verified by script and by a replica model)
Memory: 23.9 KB (float32), 6.0 KB (int8)

2. OPERATION COUNT OF THE NN (THEORY)
--------------------------------------------------------------------------------
Rule for a dense layer: y = W x + b, W in R^(n_out x n_in) -> n_in * n_out MACs
1 MAC (multiply-accumulate) = 2 FLOPs (1 multiplication + 1 addition)

Script output (export_and_count_v2.py, run on laptop with RMSE_RL_1_old.keras):

Layer                   Type                      MACs    Params  Note
protocol_embedding      Embedding                    0        28  table lookup
lstm                    LSTM                       864       320  3 time steps
lstm_scalar             Dense                        8         9
dense                   Dense                      416       448
batch_normalization     BatchNormalization           0       128  folded into Dense
dense_1                 Dense                    2,048     2,112
batch_normalization_1   BatchNormalization           0       256  folded into Dense
dense_2                 Dense                    2,048     2,080
batch_normalization_2   BatchNormalization           0       128  folded into Dense
dense_3                 Dense                      512       528
batch_normalization_3   BatchNormalization           0        64  folded into Dense
q_out                   Dense                       16        17
Total per candidate                              5,912     6,118

Hand calculation (as written in the paper):
  Dense layers: 13x32 + 32x64 + 64x32 + 32x16 + 16x1
              = 416 + 2,048 + 2,048 + 512 + 16 = 5,040 MACs
  LSTM: per step, 4 gates x u(1+u) with u=8 -> 4 x 8 x 9 = 288 MACs
        3 steps -> 864 MACs
  Dense 8->1 after LSTM: 8 MACs
  Embedding: 0 (lookup); BatchNorm: 0 (merged into previous layer at inference)
  TOTAL = 5,040 + 864 + 8 = 5,912 MACs = 11,824 FLOPs per candidate network

Per decision (N candidates):
   N     MACs per decision    FLOPs per decision
   1                 5,912                11,824
   5                29,560                59,120
  10                59,120               118,240
  17               100,504               201,008

Preprocessing cost (added to the paper as one sentence):
  - normalization: 8 parameters x ~4 ops (2 comparisons, 1 subtraction, 1 division) = 32
  - velocities: 3 x ~4 ops (1 subtraction, 1 multiplication, 2 comparisons for clip) = 12
  - total ~44 operations per candidate (~0.4% of 11,824 FLOPs)

TFLite converter's own estimate (includes element-wise ops such as activations,
additions and LSTM gate operations, not only matrix multiplications):
  N=1:  0.019 M ops = 0.009 M MACs
  N=5:  0.095 M ops = 0.047 M MACs
  N=10: 0.189 M ops = 0.095 M MACs
  N=17: 0.322 M ops = 0.161 M MACs  (~9,500 MACs per candidate)
  -> The paper reports the standard count (5,912 MACs, matrix multiplications only).
     Both counts are of order 10^4 operations per candidate.


--------------------------------------------------------------------------------
3. OPERATION COUNT OF THE MCDM METHODS (THEORY)
--------------------------------------------------------------------------------
Counting every arithmetic operation (add, subtract, multiply, divide, comparison,
square root, power) per attribute of each candidate. Operations done only once
per attribute (independent of N) are neglected. M = number of attributes = 10.

SAW (min-max normalization + weighted sum):
  2 comparisons (min and max) + 1 subtraction + 1 division (normalization)
  + 1 multiplication + 1 addition (weighted sum)
  = 6 per attribute -> ~6M = ~60 operations per candidate

WPM:
  1 comparison (max for benefit / min for cost) + 1 division (normalization)
  + 1 power (weight exponent) + 1 multiplication (product)
  = 4 per attribute -> ~4M = ~40 operations per candidate
  (the power operation costs many more cycles than a multiplication)

TOPSIS (vector normalization):
  2 (square + addition for the column norm) + 1 division (normalization)
  + 1 multiplication (weighting) + 2 comparisons (ideal and anti-ideal)
  + 6 (two distances: subtraction, square, addition, twice)
  = 12 per attribute -> ~12M = ~120, plus 4 per candidate
    (2 square roots + 1 addition + 1 division for the closeness) = ~124

Summary: 40 to 124 operations per candidate (M=10)
NN: 11,824 FLOPs per candidate -> ~100 to 300 times more ("two orders of magnitude")
  11,824/124 = 95;  11,824/60 = 197;  11,824/40 = 296

NOTE: an earlier rough estimate in the session ("4M and 7M", "40 to 70") was wrong;
the counts above are the corrected ones used in the paper.


--------------------------------------------------------------------------------
4. ASYMPTOTIC COMPLEXITY
--------------------------------------------------------------------------------
N = number of candidate networks, M = number of attributes
  SAW, WPM, TOPSIS: O(NM) per decision
  NN: O(N) per decision (constant cost per forward pass: fixed architecture,
      fixed 3 velocity values; argmax is also O(N))
  With M fixed, all methods are linear in N -> Big-O does not distinguish them;
  the constant per candidate must be analyzed (operation count + measurements).
  Fuzzy method left out (depends on the rule implementation).
Subsection title chosen: "Computational Complexity Analysis" (label sec:complexity)

5. MODEL EXPORT TO TENSORFLOW LITE
--------------------------------------------------------------------------------
Script: export_and_count_v2.py (final version)
Command (laptop):
  python export_and_count_v2.py --model RMSE_RL_1_old.keras --out tflite_models

What the script does:
  1. Loads the Keras model, counts MACs and parameters from the real weight shapes.
  2. Creates a copy with the LSTM unrolled over its 3 time steps (same weights,
     identical outputs; about 2x faster in a test: ~9 us vs ~18 us).
  3. Adds a "protocol guard": protocol index -> index mod 7 (FLOOR_MOD op).
     Identical outputs for valid indices 0..6. Needed because the Android
     benchmark tool feeds random integers, which crashed the embedding lookup.
  4. Exports one model per N in {1, 5, 10, 17}, with fixed input shapes, via
     model.export(SavedModel) -> TFLiteConverter.from_saved_model.
  5. Two versions per N: fp32, and int8 (dynamic-range quantization,
     tf.lite.Optimize.DEFAULT, weights only).
  6. Checks max |TFLite output - Keras output| on random inputs.

Final export results (v2, with FLOOR_MOD):
  Model              Size      max |TFLite - Keras|
  nn_N1_fp32         34.6 KB   9.54e-07
  nn_N1_int8         23.8 KB   3.03e-04
  nn_N5_fp32         34.8 KB   4.77e-07
  nn_N5_int8         24.0 KB   3.06e-03
  nn_N10_fp32        34.8 KB   9.54e-07
  nn_N10_int8        24.0 KB   6.64e-03
  nn_N17_fp32        34.8 KB   9.54e-07
  nn_N17_int8        24.0 KB   4.64e-03
  -> fp32: differences < 1e-6 (paper states "below 10^-6")
  -> int8: differences up to ~7e-3 (could occasionally change the chosen network
     when two candidates have almost equal scores; paper reports fp32)

Operations inside the final model (nn_N17_fp32):
  ADD, CONCATENATION, DELEGATE, FLOOR_MOD, FULLY_CONNECTED, GATHER, LESS,
  LOGISTIC, MUL, RESHAPE, SELECT, SPLIT, TANH, TRANSPOSE, UNPACK

On the phone, XNNPACK delegated 47 of 53 nodes (46 of 52 for N=1),
4 partitions, 2 delegate kernels.

6. BENCHMARK METHOD
--------------------------------------------------------------------------------
Laptop and Raspberry Pi: benchmark_decision.py
  (copy on the Pi named benchmark_decision_rasp.py; same code)
  Commands:
    Laptop: python benchmark_decision.py --models tflite_models
    Pi:     taskset -c 3 python benchmark_decision_rasp.py --models tflite_models

  Settings:
    - single thread (Interpreter num_threads=1)
    - warm-up: 500 decisions; measured: 10,000 decisions per method per N
    - timer: time.perf_counter_ns, each decision timed individually
    - statistics: mean, std, median, p95, p99 (microseconds)
    - inputs: random, seed np.random.RandomState(0), 256 pre-generated samples
      reused cyclically (generation not timed)
        NN raw parameters: uniform(0.1, 1.0), shape (N, 8)
        distances: start uniform(10, 1000) m + cumulative steps uniform(-1.5, 1.5)
        protocol: random integers 0..6
        MCDM matrix: uniform(0.1, 1.0), shape (N, 10) (> 0 for WPM)
    - MCDM: vectorized NumPy, M=10, weights 1/10,
      directions [1,1,1,0,0,0,1,0,0,0] (1 = benefit), same as the simulator
        SAW: min-max normalization with direction, weighted sum, argmax
        WPM: x/max (benefit) or min/x (cost), product of powers, argmax
        TOPSIS: vector normalization, weighting, ideal/anti-ideal,
                Euclidean distances, closeness, argmax
    - NN rows:
        "NN-fp32/NN-int8" = FULL decision as in the simulator:
          normalization of 8 parameters + velocity computation + inference + argmax
          (preprocessing verified identical to the simulator's normalizeInputs and
           velocity code: max difference 3e-8, float32 rounding)
        "infer-fp32/infer-int8" = inference only (set tensors, invoke, argmax)
    - Includes Python interface overhead -> conservative (upper-bound) estimates.

Smartphone: official TensorFlow Lite benchmark tool (native C++, no Python)
  Binary: android_aarch64_benchmark_model (TFLite nightly), via adb
  Command per model:
    adb shell taskset <mask> /data/local/tmp/benchmark_model
        --graph=/data/local/tmp/tflite_models/<model>.tflite
        --num_threads=1 --use_xnnpack=true --warmup_runs=500 --num_runs=10000
  Masks: f0 = cores 4-7 (Cortex-A78, performance)
         0f = cores 0-3 (Cortex-A55, efficiency)
  Measures inference only (no preprocessing, no MCDM methods).
  Reports per run: count, min, max, avg, std, p5, median, p95 (integer us for
  percentiles), Init time, First inference, memory footprint.
  The tool runs "at least 10,000 iterations and at least 1 s", so counts are
  larger than 10,000.

14. PROBLEMS FOUND AND HOW THEY WERE SOLVED
--------------------------------------------------------------------------------
1. Keras 3 conversion via concrete function produced resource variables / WHILE
   loop -> switched to model.export(SavedModel) + from_saved_model.
2. LSTM converted as WHILE loop (slower) -> exported with unroll=True.
3. First benchmark timed the NN without preprocessing (unfair) -> NN now timed
   over the full decision; inference-only kept as a separate row.
4. Clip-based protocol guard failed conversion (needs flex op Relu6 on int) ->
   replaced by modulo (FLOOR_MOD, standard op).
5. Android benchmark: "gather index out of bounds" with random protocol inputs
   -> solved by the modulo guard (export_and_count_v2.py).
6. Old results_phone.txt re-read by mistake (identical timing line) -> file
   deleted and runs repeated.
7. Pi 32-bit (Buster, Python 3.7): no ai-edge-litert; old tflite-runtime 2.5
   cannot read FULLY_CONNECTED v12 -> Pi reinstalled with 64-bit OS.
8. benchmark script made compatible with old NumPy (RandomState instead of
   default_rng; randint instead of integers).
9. University Wi-Fi isolated devices (ssh timeout) -> phone hotspot / other network.
10. TOPSIS division by zero for N=1 -> guarded denominator.

17.1 Mobility model (car): Gauss-Markov
  mean velocity 15 m/s, iteration 100 ms (1.5 m per iteration)
  alpha = 0.95, speed noise std = 15% of mean speed, direction noise std = 6 deg,
  max turn per iteration = 8 deg, reflection at the borders of the 1000x1000 m area
  Note: in the code the direction term has no mean direction (random walk on the
  heading); speed follows a true Gauss-Markov process.

17.2 NN training settings (paper)
  100 simulations x 600 iterations; epsilon 1 -> decay 0.9975 per training step;
  Adam, lr 3e-4 (the 3e-5 switch is commented out in the current code),
  Huber loss, gradient clipnorm 1.0, batch 32, replay buffer 8192,
  warm-up 2048, TMC window 10, gamma 0.95, reward = -nRMSE.
  Testing: epsilon 0, training deactivated.
